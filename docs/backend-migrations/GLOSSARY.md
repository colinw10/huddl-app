# Migrations Glossary

Quick definitions for everything you need to know.

---

## Database Terms

### Database

A organized collection of data stored electronically. Think of it as an Excel workbook with multiple sheets.

### Table

One "sheet" in the database. Examples: `users`, `posts`, `friends`. Each table stores one type of thing.

### Row (Record)

One item in a table. Example: One specific user, one specific post.

### Column (Field)

One piece of information about each item. Examples: `username`, `email`, `created_at`.

### Primary Key (PK)

The unique ID for each row. Usually called `id`. No two rows can have the same PK.

### Foreign Key (FK)

A reference to another table. Example: A post has `author_id` that points to a user's `id`.

---

## SQL Terms

### SQL (Structured Query Language)

The language databases understand. You write SQL commands to create tables, add data, find data, etc.

### CREATE TABLE

SQL command to make a new table.

```sql
CREATE TABLE posts (
    id INTEGER PRIMARY KEY,
    content TEXT,
    author_id INTEGER
);
```

### INSERT

SQL command to add a row.

```sql
INSERT INTO posts (content, author_id) VALUES ('Hello!', 1);
```

### SELECT

SQL command to find data.

```sql
SELECT * FROM posts WHERE author_id = 1;
```

---

## Database Software

### PostgreSQL (Postgres)

A powerful, production-ready database server. Runs as a separate program on your computer. Best for real apps.

### SQLite

A simple file-based database. Your whole database is just one file (`db.sqlite3`). Good for development.

### Which Should I Use?

- **Development:** SQLite is fine (already set up in your project)
- **Production/Team:** PostgreSQL (more robust, everyone can connect to same server)

## Django Terms

### Django ORM

ORM = Object Relational Mapping. Lets you write Python instead of SQL. Django translates your Python code to SQL.

### Model

A Python class that defines a database table. Each class = one table. Each attribute = one column.

```python
class Post(models.Model):          # Creates 'posts_post' table
    content = models.TextField()    # Creates 'content' column
    author = models.ForeignKey(User) # Creates 'author_id' column
```

### models.py

The file where you define your models. Each Django app has its own `models.py`.

### App

A module in Django that handles one feature. Your project has 3 apps: `users`, `posts`, `friends`.

---

## Migration Terms

### Migration

A file containing instructions for changing the database. Auto-generated by Django from your models.

### Migration File

Python file in `migrations/` folder. Named like `0001_initial.py`, `0002_add_likes.py`.

### makemigrations

Command that reads `models.py` and creates migration files.

```bash
python manage.py makemigrations
```

**Does NOT change the database!**

### migrate

Command that reads migration files and runs them on the database.

```bash
python manage.py migrate
```

**This actually changes the database!**

### showmigrations

Command to see which migrations have been applied.

```bash
python manage.py showmigrations
```

### Initial Migration

The first migration for an app. Usually called `0001_initial.py`. Creates the table.

### Migration Conflict

When two people create migrations with the same number (like both creating `0002_*`). Git can't merge them automatically.

---

## Data Sharing Terms

### dumpdata

Command to export database data to a JSON file.

```bash
python manage.py dumpdata users --indent 2 > users_data.json
```

### loaddata

Command to import data from a JSON file into the database.

```bash
python manage.py loaddata users_data.json
```

### Fixture

A JSON file containing database data. Used for seeding or sharing data.

### Seed Data

Initial data to populate an empty database. Example: test users, sample posts.
