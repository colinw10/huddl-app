🔄 KEY FLOWS - FRONTEND ↔ BACKEND
═══════════════════════════════════════════════════════════

These are the flows you MUST be able to explain in interviews:

📍 FLOW 1: Creating a Post
─────────────────────────────────────────────────────────
Frontend:
  1. User types in ComposerModal textarea
  2. Clicks "Post" button → handleSubmit()
  3. PostsContext.createPost(data) called
  4. postsService.create(data) called
  5. apiClient.post('/posts/', data) - JWT added automatically

Backend:
  6. POST /api/posts/ → posts/urls.py router
  7. PostViewSet.create() in posts/views.py
  8. PostSerializer validates data
  9. Post.objects.create() saves to database
  10. Returns new post as JSON (201 Created)

Frontend (response):
  11. postsService returns response.data
  12. PostsContext adds new post to state
  13. Components re-render with new post

📍 FLOW 2: User Login
─────────────────────────────────────────────────────────
Frontend:
  1. User enters email/password in Login.jsx
  2. handleSubmit() calls AuthContext.login()
  3. apiClient.post('/auth/login/', credentials)

Backend:
  4. POST /api/auth/login/ → users/urls.py
  5. email_login() in users/views.py
  6. Validates credentials, generates JWT tokens
  7. Returns { access: "...", refresh: "...", user: {...} }

Frontend (response):
  8. AuthContext stores tokens in localStorage
  9. Sets currentUser state
  10. Redirects to /home

📍 FLOW 3: Liking a Post
─────────────────────────────────────────────────────────
Frontend:
  1. User clicks heart icon in TimelineRiverRow
  2. handleLike() calls PostsContext.likePost(id)
  3. postsService.like(id) called
  4. apiClient.post(`/posts/${id}/like/`)

Backend:
  5. POST /api/posts/123/like/ → posts/urls.py
  6. PostViewSet.like() - @action decorator
  7. Checks if Like exists for user+post
  8. If exists: delete (unlike), else: create (like)
  9. Updates post.likes_count
  10. Returns updated post JSON

Frontend (response):
  11. PostsContext updates post in state
  12. Heart icon toggles filled/outline
  13. Like count updates

📍 FLOW 4: Loading User Profile
─────────────────────────────────────────────────────────
Frontend:
  1. User clicks on username link
  2. React Router navigates to /profile/:username
  3. Profile.jsx mounts, useParams() gets username
  4. useEffect fetches user data + posts
  5. postsService.getByUsername(username)
  6. apiClient.get(`/posts/?username=${username}`)

Backend:
  7. GET /api/posts/?username=pablo → posts/urls.py
  8. PostViewSet.get_queryset() filters by username
  9. Returns user's posts as JSON array

Frontend (response):
  10. Profile.jsx sets userPosts state
  11. ProfileCard + TimelineRiver render

📍 FLOW 5: Sending Friend Request
─────────────────────────────────────────────────────────
Frontend:
  1. User clicks "Add Friend" button
  2. FriendsContext.sendRequest(userId)
  3. friendsService.sendRequest(userId)
  4. apiClient.post(`/friends/request/${userId}/`)

Backend:
  5. POST /api/friends/request/5/ → friends/urls.py
  6. send_request(request, user_id) in friends/views.py
  7. Creates FriendRequest(from_user, to_user)
  8. Returns success message

Frontend (response):
  9. Button changes to "Request Sent"

🎤 INTERVIEW FOCUS AREAS
═══════════════════════════════════════════════════════════

🎤 "Explain how a post gets created"
   → ComposerModal → PostsContext.createPost() → 
   → postsService.create() → apiClient.post() →
   → Backend: POST /api/posts/ → PostViewSet.create()

🎤 "How does authentication work?"
   → Login.jsx → apiClient.post('/auth/login/') →
   → Backend returns JWT → AuthContext stores in localStorage →
   → apiClient interceptor adds token to all requests

🎤 "What are Vite path aliases?"
   → @assets, @components, @contexts, @services, @utils
   → Cleaner imports: '@assets/icons' vs '../../../../../../assets/icons'
   → Configured in vite.config.js

🎤 "Walk me through your component architecture"
   → Context API for global state (Auth, Posts, Friends)
   → Services layer for API calls (separation of concerns)
   → Components consume contexts via useContext hooks
   → Modular SCSS with partials (_variables, _mixins, etc.)

🎤 "How do you handle errors?"
   → apiClient has response interceptor for 401 (unauthorized)
   → Components use try/catch for API calls
   → Display error messages in UI

🎤 "Why Context API over Redux?"
   → Simpler for our scale (3-4 contexts)
   → Less boilerplate, built into React
   → Each context has clear domain (auth, posts, friends)
